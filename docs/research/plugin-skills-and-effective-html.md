## Source-to-package coupling and conformance

**Verified: packaging now uses the pinned upstream source directly.** `.gitmodules` points `.agents/skills` to `mattpocock/skills`; the root curation manifest pins the same repository and commit and lists 27 skills under `engineering` and `productivity`. The package builder validates each selected path and name, then compares the selection with every immediate category directory containing a `SKILL.md`. A missing or extra path fails the build. ([submodule source](../../.gitmodules#L1-L3), [curation policy and selection](../../git-bbq-curation.json#L4-L36), [completeness enforcement](../../scripts/build_git_bbq_plugin.py#L94-L165))

The build checks that the submodule `HEAD`, `origin`, and clean working tree match the root pin. It then exports selected skill paths from that exact Git commit with `git archive`; when the submodule is absent, it clones and checks out the same pin first. This prevents modified, ignored, or untracked submodule files from becoming package content while retaining a misleading commit identity. The package manifest records each skill's upstream path, name, repository, and commit. ([pin and clean-checkout enforcement](../../scripts/build_git_bbq_plugin.py#L184-L234), [exact commit archive](../../scripts/build_git_bbq_plugin.py#L237-L271), [source manifest](../../scripts/build_git_bbq_plugin.py#L335-L353), [development workflow](../../docs/DEVELOPMENT.md#L31-L56))

The selected skills are projected into immediate `skills/<upstream-name>/` directories for plugin discovery. The builder preserves upstream instructions and support files, with a narrow metadata adapter: it removes `disable-model-invocation: true` only after checking adjacent Codex metadata sets `allow_implicit_invocation: false`, and maps upstream's nonstandard `argument-hint` into `metadata.git-bbq-argument-hint` because the Agent Skills frontmatter schema does not accept that field. Skill instruction bodies and auxiliary content remain byte-for-byte source exports. The package validator checks the selected skill directory set, frontmatter fields, and exact directory/name match. Fresh artifacts passed the [Agent Skills reference validator](https://github.com/agentskills/agentskills/tree/69ef37e9424c0a7ea9dd2293b559e43ec8176379) for all 27 projected skills and passed the [Agent Plugins skill directory layout](https://agent-plugins.org/plugin-authors/skills#directory-layout) and manifest schema checks. ([projection and license copy](../../scripts/build_git_bbq_plugin.py#L274-L285), [metadata adapter](../../scripts/build_git_bbq_plugin.py#L288-L332), [package conformance checks](../../scripts/validate_git_bbq_plugin.py#L120-L171))

The upstream MIT license is included in the same pinned archive and copied to `licenses/mattpocock-skills/LICENSE`; the validator requires that package path. The repository's third-party notice now identifies the upstream repository and pin. ([archive includes upstream license when present](../../scripts/build_git_bbq_plugin.py#L237-L254), [license packaging](../../scripts/build_git_bbq_plugin.py#L274-L280), [license validation](../../scripts/validate_git_bbq_plugin.py#L149-L153), [upstream MIT license](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/LICENSE), [third-party notice](../../THIRD_PARTY_NOTICES.md#L10-L15))

**Remaining scope caveat (inference):** the builder operationalizes “stable” as every immediate `engineering` or `productivity` child that has a `SKILL.md`; it does not inspect a separate stability field. If upstream later places an explicitly in-progress skill in those directories, completeness enforcement would include it until the policy or discovery rule is updated. ([discovery rule](../../scripts/build_git_bbq_plugin.py#L94-L105), [curation policy](../../git-bbq-curation.json#L8-L9))

## Upstream workflows and repository integration

The pinned upstream catalog supplies setup, triage, architecture review, specification, ticket, implementation, and planning workflows, alongside reusable engineering and productivity skills such as prototype, research, TDD, domain modeling, code design, and review. ([pinned engineering catalog](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/README.md), [pinned complete repository](https://github.com/mattpocock/skills/tree/b0618bc436ad893b3c5e84e55fba86586d34a404))

- **Setup:** the upstream setup skill offers GitHub, GitLab, local Markdown under `.scratch/`, or another tracker described by the user. It also establishes the five triage labels and root domain-document rules. For this repository, the setup contract is now recorded in `docs/agents/`: GitHub Issues via `gh`, the default five labels, and the domain-doc integration rules. ([upstream setup choices and behavior](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/setup-matt-pocock-skills/SKILL.md#L7-L15), [tracker choices](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/setup-matt-pocock-skills/SKILL.md#L38-L61), [local GitHub tracker contract](../../docs/agents/issue-tracker.md#L1-L33), [triage labels](../../docs/agents/triage-labels.md#L1-L13), [domain rules](../../docs/agents/domain.md#L1-L13))
- **Triage:** upstream recommends one category and one state role, verifies issue claims against the code, and waits for maintainer direction before applying a disposition. Comments or issues it posts must carry an AI-generated notice. It can include pull requests only when the configured tracker says PRs are request submissions. This repository explicitly limits triage to GitHub Issues, which is consistent with the local tracker document. ([upstream triage workflow](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/triage/SKILL.md#L13-L17), [roles and PR scope](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/triage/SKILL.md#L24-L45), [verification and action](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/triage/SKILL.md#L68-L90), [local issue-only policy](../../docs/agents/issue-tracker.md#L22-L26))
- **To spec:** synthesizes the current conversation, explores the code and testing seams, asks the user to confirm those seams, then publishes the spec with the ready-for-agent label. ([pinned `to-spec`](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/to-spec/SKILL.md#L7-L20))
- **To tickets:** breaks an approved plan or spec into independently verifiable tracer-bullet slices, asks the user to approve ticket granularity and blocking edges, then publishes in dependency order. Upstream supports local Markdown files and real trackers such as GitHub or Linear; setup additionally offers GitLab and a freeform “other” backend. This repository is configured specifically for GitHub Issues. ([pinned `to-tickets`](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/to-tickets/SKILL.md#L25-L67), [upstream tracker options](https://github.com/mattpocock/skills/blob/b0618bc436ad893b3c5e84e55fba86586d34a404/skills/engineering/setup-matt-pocock-skills/SKILL.md#L38-L49), [repository GitHub backend](../../docs/agents/issue-tracker.md#L1-L20))

The GitHub backend supports community-visible debugging: specs can be parent issues, implementation tickets can be linked as native sub-issues when available, and native `blocked by` relationships can show dependency order. The local documentation supplies textual fallbacks (`Part of #N` and `Blocked by: #N`). GitHub documents these issue dependency operations for both the UI and `gh`. ([repository issue operations](../../docs/agents/issue-tracker.md#L8-L20), [GitHub issue dependency documentation](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/creating-issue-dependencies))

## Effective HTML companion fit

Effective HTML is a useful optional companion when a product or architecture decision benefits from visual review. Recommend `design-artifact` for visual product direction; `html-wireframe` and `html-prototype` for interaction exploration; and `html-diagram` and `html-plan` for architecture relationships and roadmap sequences. Git BBQ examples include comparing setup or triage flows, prototyping realistic review states, diagramming the upstream-to-package path and lifecycle-hook effects, and showing a staged migration. These artifacts make decisions easier to review; Git BBQ's code, tests, and ADRs remain the durable implementation and decision record. Skip an HTML artifact when it adds no review value to a question already settled by code, tests, or a short ADR. Keep Effective HTML separately installed. ([Effective HTML skill catalog and use cases](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/README.md#L34-L46), [wireframe workflow](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html-wireframe/SKILL.md#L31-L80), [prototype workflow](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html-prototype/SKILL.md#L8-L17), [diagram workflow](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html-diagram/SKILL.md#L8-L46), [plan workflow](https://github.com/plannotator/effective-html/tree/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html-plan))

Matt's architecture-review workflow already requests a self-contained report but its scaffold loads Tailwind and Mermaid from CDNs. Effective HTML's broad and specialist artifact contracts require inline essentials and no network or external service unless the user permits it. As written, the architecture report can lose styling or diagrams offline. Align the report scaffold with Effective HTML by using inline CSS and SVG, or make CDN use an explicit, user-approved dependency. ([architecture skill](../../.agents/skills/skills/engineering/improve-codebase-architecture/SKILL.md#L37-L41), [CDN report scaffold](../../.agents/skills/skills/engineering/improve-codebase-architecture/HTML-REPORT.md#L1-L16), [Effective HTML standalone contract](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html/SKILL.md#L60-L73), [diagram standalone contract](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/skills/html-diagram/SKILL.md#L42-L46))

Effective HTML is separately installable as a Codex plugin, so it can remain an optional companion rather than expanding Git BBQ's source pin, curation, license, and package surface. ([Effective HTML Codex installation](https://github.com/plannotator/effective-html/blob/2ac1dfecb0f2474e75260cb6d3c9b9d6d9b5062e/README.md#L74-L79), [ADR decision](../../docs/adr/0001-upstream-skills-and-package-boundary.md#L44-L47))

## OpenAI distribution constraint

The local package declares `extensions.com.openai.hooks` and includes the five Codex lifecycle hooks. OpenAI's current plugin guidance supports hooks for manually installed Codex desktop plugins and excludes packages containing them from the public plugin directory. Git BBQ now builds a distinct hook-free public-oriented variant while preserving the local variant. This removes the hook-specific eligibility issue, but the bundled CLI still cannot access local repositories from ChatGPT web; hosted operations need a remote integration. ([portable manifest template](../../adapters/codex/templates/git-bbq-plugin.json#L14-L24), [variant build](../../scripts/build_git_bbq_plugin.py), [submission notes](../../docs/PLUGIN_SUBMISSION.md), [OpenAI lifecycle-hook and directory guidance](https://developers.openai.com/plugins/build/plugins#bundled-mcp-servers-and-lifecycle-hooks))

OpenAI documents an optional `extensions.com.openai.onboardingSkill` field for pointing a plugin at a bundled onboarding skill. Git BBQ now declares the bundled upstream setup skill in the portable manifest and preserves that field in the Codex compatibility manifest. The package validator checks that the path is the setup skill and that the file is present. This gives new installers a direct setup entry point without changing the skill's upstream content. ([OpenAI onboarding guidance](https://developers.openai.com/plugins/build/plugins#add-an-onboarding-skill), [portable manifest](../../adapters/codex/templates/git-bbq-plugin.json#L14-L18), [compatibility manifest generation](../../scripts/build_git_bbq_plugin.py#L356-L379), [validator](../../scripts/validate_git_bbq_plugin.py#L135-L160))
